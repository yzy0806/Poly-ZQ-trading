**IBKR callback reconciliation validation — 2026-09-11**

1. **Reproduced incident.** A temporary database starts with verified opening inventory of 23 ZQ and the two Polymarket positions. The pre-fix regression test failed when a known one-contract order's position callback arrived before its execution: the engine disarmed immediately. The implementation passes all six permutations of position, execution, and status callbacks without a lasting pause, records exactly one IBKR execution and two hedge obligations, and reaches CLEAN after confirmed hedge evidence.

2. **Additional behavior.** Tests cover terminal and delayed working callbacks; a fresh read that still conflicts; unique execution request IDs; overlapping refresh prevention; stale completion markers; independent deadline expiry without incoming callbacks; duplicate callbacks that cannot extend the deadline; unknown orders, executions, foreign clients, and identity conflicts during a pending gap; partial fills and late fills after cancellation; manual pause preservation; restart disarming; and rejection of cached clean authorization during a refresh. Existing execution recovery, inventory, hedge reservation, risk, and shutdown tests also pass.

3. **Local checks.** The full Python suite, Ruff, mypy, dashboard tests, dashboard lint, and production dashboard build pass. The dashboard suite contains 17 tests. The final Python suite contains 316 tests. These are offline tests with isolated databases and mocked venues; they do not submit broker or Polymarket orders.

4. **Package checks.** The declared Hatchling build produces a source distribution and wheel. The wheel's coordinator, configuration, and opening-inventory code match the local source. A smoke import loads the packaged coordinator with the explicit deployment example in READ_ONLY mode and the 2-second setting. Package inventories exclude the local `.env`, databases, private keys, and certificates. The dashboard production bundle also builds successfully. Docker is unavailable on this workstation, so a new container image and Linux/Python 3.12 execution have not been validated here; the existing GitHub Actions workflow supplies those release checks after commit/push.

5. **Deployment.** `IBKR_CALLBACK_SETTLE_SECONDS=2` is present in the local `.env` and `deploy/zq-arb.env.example`. Existing VPS environment files must include it before upgrading. The setting is required and bounded to greater than zero and at most ten seconds. It is not an extension of the Polymarket settlement deadline. No database migration or purge is required for this callback fix. Previously added opening-inventory files remain part of the uncommitted local change set and must be included in the intended deployment commit.

6. **Operational state.** Implementation did not start or restart the trading runtime, change live database records, place or cancel real orders, deploy to the VPS, or re-arm trading. The running process needs a controlled restart to load the new code. A previously latched pause is not automatically cleared by installing this release.
