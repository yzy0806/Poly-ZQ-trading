**IBKR callback deadline during account refresh — 2026-09-14**

1. **Problem.** A known ZQ partial fill can reach the execution ledger inside the two-second callback window while the separately requested account refresh is still waiting for completion markers. The previous classifier returned before comparing fill evidence whenever any snapshot component was incomplete. Its watchdog therefore remained active and could pause and cancel the residual even after the fill discrepancy had resolved. The new regression failed against the original coordinator before the implementation change.

2. **Implementation.** After a clean authenticated reconciliation, retain accepted target-contract positions and update that view from live position callbacks. Account refreshes continue rebuilding a separate snapshot. During a refresh, compare the retained live evidence with durable executions, cumulative reported fills, terminal completion and order conflicts. When the callback evidence agrees, clear the gap and cancel the watchdog immediately. The resolution audit records the agreeing expected/observed quantities and whether the full refresh remains pending. Completed position snapshots replace the retained view, accounting for omitted positions, and disconnect discards it.

3. **Safety boundaries.** Retained callback evidence cannot authorize new entries or mark an incomplete account snapshot CLEAN. Startup requires a clean baseline before this view is available. The callback deadline remains unchanged; unresolved gaps still expire and duplicates cannot extend it. The full account-refresh timeout remains independent. Unknown orders, unknown executions, foreign clients, identity conflicts and contradictory positions continue to pause. Later matching evidence cannot clear an already latched safety or operator pause. Hedge obligations still come only from unique actual executions, including fills received after cancellation.

4. **Regression coverage.** Twenty-four additional parameterized cases cover all six callback orderings for one fill out of five contracts, each of the four delayed snapshot end markers, missing position/execution/status evidence, contradictory positions, refresh timeout after gap resolution, another partial or late fill during the same refresh, an empty completed position snapshot, disconnect, and independent faults during an incomplete refresh. The delayed-marker tests wait beyond the configured callback deadline and verify that entries remain blocked until full reconciliation completes.

5. **Validation.** `python -m pytest -q`: **343 passed in 75.05 seconds**. `python -m ruff check src tests`: passed. `python -m mypy src`: passed for all 37 source files. Ruff formatting checks passed for both changed Python files. These are local tests with isolated databases and mocked venues. They do not establish production deployment or real-venue timing under the updated code.

6. **Release scope.** The change requires no environment update or database migration. The example callback setting remains two seconds. No production deployment, restart, configuration change, or trading control action was performed as part of this implementation. A running engine must load the updated code through the normal deployment process before the fix takes effect.
